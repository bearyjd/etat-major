# AGENTS.md: working in this repo (for Codex and other coding agents)

État-major is a self-hosted visual product-development workspace: research and decisions, how the code works, what to build, and evidence of progress. Read `CLAUDE.md` for the hard constraints, then `docs/NEXT.md` for the current state and the next tasks. The design is in `docs/VISUALIZATION-ARCHITECTURE.md` and `docs/TRACEABILITY.md`; the tool decisions are in `docs/TOOL-EVALUATION.md` and `docs/FLOORPLAN-PROOF.md`.

## Rules that are easy to get wrong
- Never store, proxy or pool Claude or Codex credentials. Never call a model or the network from product code. `src/` and the `etat-major` CLI make no network or `gh` call, with no exception.
- Git holds intent. Derived values (running, review, verified, drift tiers) are computed, never written to files. Only a human records a Decision, acceptance or "reviewed"; tooling writes only `proposed`, `unreviewed` or `draft`.
- Everything read from disk is untrusted: no symlink following, size caps, depth caps, escape printed text with `safe()`, turn every parse failure into a file-and-field error (no tracebacks). Never print absolute paths or remotes from third-party data.
- Never execute Gradle, Floorplan's model steps, `trail init`, or anything from a scanned repository. Git may be called only as a read-only subprocess with a fixed argument list and no shell (the exceptions are the narrow wrapper allowance described in `docs/NEXT.md`, tasks 2 and 3, and the separate capture-script exception below).
- **Capture-script exception (`scripts/record_github.py` only).** A maintainer-run script outside `src/` may exec exactly one external tool, `gh`, to record the two files in `docs/contracts/progress-evidence.md`. It uses the fixed argument lists in that contract, no shell, a timeout, an output size cap and an environment built from an allow-list (`PATH`, `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`, `GH_CONFIG_DIR`, `LANG`, `LC_ALL`; `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` only let `gh` reach a system keyring and carry no secret themselves). Every other variable is dropped, including any token variable such as `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and `GITHUB_ENTERPRISE_TOKEN`. It refuses to run if `GH_HOST` or `GH_REPO` is set and never passes `--repo`. `gh` authenticates itself from the maintainer's own login (its config directory or system keyring). Because `gh` may keep that credential in a plaintext config file under the allowed `HOME`, the guarantee is that the script itself never opens, copies, logs or writes it, not that `gh` cannot read it. Token-only environment auth is unsupported. It also sets `GH_PROMPT_DISABLED=1`, `GH_NO_UPDATE_NOTIFIER=1`, `NO_COLOR=1` and `GH_PAGER=cat`, closes stdin, and passes no proxy, pager, browser, editor or debug variable. It runs `gh` with its working directory set to a checkout the human names, prints the resolved host and `owner/repo` for the human to confirm before writing anything, and sets `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0` and `GIT_OPTIONAL_LOCKS=0`. That checkout's remotes are untrusted data, so the confirmation is part of the contract. It writes only into a directory the human names, atomically, without following symlinks, and creates no file on failure. Tests use a fake `gh`; only the maintainer runs it against a real repository. It refuses to start unless stdin is an interactive terminal (a guard against accidental automation, not proof of a person). It is run only by a person at a terminal: no `src/` module, console entry point, web route, hook, CI job or scheduler may import, spawn or expose it. A test must scan `src/` and fail if it gains a `gh` literal, a network import or a reference to `scripts/`, or if a new module imports `subprocess` (the current importers, `evidence_git`, `floorplan_runner`, `renames` and `trail_runner`, are an explicit allow-list). The script does not exist yet; this entry only permits writing it. Anything else still follows the bans above.
- Do not add dependencies. The maintainer approved the optional Planning web extra and its test client. There is no network in the dev environment.
- Keep personal paths, hostnames, emails and keys out of the repo.

## How to work
- Strict TDD: a failing test first, then the minimum code. Functions under 50 lines, files under 400, frozen models, error messages naming file and field.
- Gates before you call anything done: `pytest` (coverage at least 80%), `ruff check .`, `ruff format --check .`. CI runs these on Python 3.12.
- **Run every new adapter on a real artifact before calling it done.** Hand-made fixtures hid four bugs that a real Kotlin repository exposed in one afternoon (see `docs/FLOORPLAN-PROOF.md`). Use a real-shaped fixture trimmed from real output, never one you invented.
- Small commits with conventional messages and no attribution lines. Do not push, open PRs or merge unless the maintainer asks. When merging is asked for, CI must be green on the PR's current head commit.
- Separate authoring from review: do not approve your own change.
- Report only what you ran. Never claim a test passes unless you ran it.
